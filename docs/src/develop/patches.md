# The patch queue

Libera Suite does not fork upstream. It pins an upstream revision and applies a series of patches to it, each one a commit with a message explaining what it is for.

```
build/upstream/pins.toml            the upstream revisions, by hash
build/upstream/patches/core/
build/upstream/patches/web-apps/
build/upstream/patches/sdkjs/
```

The pins followed Euro-Office's own desktop releases, the revisions its `DesktopEditors` repository names for a release, up to v9.3.8 on 2026-11-15. Since 2026-11-19 they are on Euro-Office's `main` (V8 14.6 in place of 8.9, and third-party libraries fetched and built rather than vendored), so that our fixes are made against what upstream is changing; eight core patches and one `web-apps` patch left the queue then, upstream having made the same fix. Up to v9.3.5-2, core carried a copy of libxml2, the XML parser the converter reads every document with, about release 2.9.4, and a 6 KB document of nested entities took that copy to 3.9 GB of memory; we built core against libxml2 2.9.14 instead, from a pin of its own, with two patches. Since v9.3.8 core builds libxml2 2.15.4 itself, from its own fetch script (`Common/3dParty/libxml2`), and the pin, its patches and core `0172` are gone.

`build/engine/build.sh fetch` applies the series with `git am`, which does not fuzz, to the pinned hash in a scratch worktree beside the repository, then checks the repository out at the result and cleans it. Only the files whose content changed are rewritten, so a build after one patch changed recompiles what that patch touches, not everything the series touches. A patch that has stopped applying is news: investigate it. The fetch then stops and leaves the build tree as it was, and the scratch worktree (`src/.<repo>-patching`) mid-`am` for a look; the next fetch removes it.

## Why a queue

The queue answers "what did Libera Suite change?" in a form anyone can check. On a long-lived branch that question becomes a diff against a moving target; a pin bump becomes one large merge. The queue gives a series of small rebases that each say what they were for.

It also makes the AGPL obligation concrete: the corresponding source for a release is a commit hash plus a patch series that provably applies to it.

## What is in it

**`core`: the build, the converter, and OpenDocument.** Patches keep their numbers when others leave the queue, so the numbering has gaps.

- *macOS.* Upstream ported the build from qmake to CMake and the port dropped the Mac branches. We put them back in a series of about twenty patches; Euro-Office has since built macOS itself, and the queue keeps only what its build still lacks: `memalign`, which macOS does not have, for openjpeg (`0018`), and two V8 build options of our own (`0009`, `0010`). The Mac does not build V8 at all since the sync with `main`: doctrenderer runs the editors' code in the system's JavaScriptCore, which upstream's CMake offered as an option and `0210` completes, so that V8 is neither built nor linked.
- *Windows.* Boost's engine built with a named toolset (`0022`), an external OpenSSL from vcpkg (`0024`), and Crypto++ given raw pointers where it names the `stdext` namespace Visual Studio 18 has removed (`0025`, which patched the vendored copy until upstream began fetching Crypto++ 8.9, and now patches the fetched one). Upstream now builds core with the DLL runtime, but not V8: Chromium links the static runtime into any non-component desktop build, and doctrenderer.dll then failed to link against an OpenSSL built for the DLL one. `0028` makes V8 use the DLL runtime too, as it did for V8 8.9, now by rewriting Chromium's `build/config/win/BUILD.gn` from upstream's V8 script, since core's libraries also hand `FILE*` handles to one another. Depot_tools runs the build's own Python on Windows too (`0211`), where the first `python3` on the path may be one `gsutil` refuses.
- *Elsewhere in the build.* Third-party builders that stream their output (`0023`), doctrenderer against an OpenSSL without MD2 (`0026`), `hypotf` bound to its old glibc version so the Linux core loads on RHEL 9 (`0032`).

- *OpenDocument* (`0101` onwards). Fixes to reading and writing `.odt`, `.ods` and `.odp`, each found against LibreOffice's own test documents.
- *A hostile document* (`0173` onwards). A picture a document links to is read from a web address only: one linked to a path on the user's disk was copied into everything written from the document (`0175`, ours). An SVG's `<image>` draws only a picture the SVG carries, not a file it names (`0174`). An `.xls` ActiveX control's data is bounds-checked without a sum that can overflow (`0173`). The last two are from ElixirOffice's fork of `core`, and so is the refusal of an encrypted Word, Excel or PowerPoint file whose integrity check fails, which x2t noted in a comment and opened all the same (`0183`, their `0010-office-integrity-rejection`, without its WebAssembly-only condition).
- *Encrypted OpenDocument.* A part whose compressed data fills its last 16-byte block is written with the full padding block AES-CBC requires, which x2t left out: LibreOffice refused about a quarter of the encrypted ODF files x2t wrote, which x2t itself read back (`0184`, from ElixirOffice's core `4c95116`).
- *A PDF's change of password.* Each stream is copied to its Length or to its end, whichever comes first, where it was copied to its Length, the length of its ciphertext: an AES stream decrypts to fewer bytes, made up with 0xFF, so changing or removing an AES PDF's password padded every stream (`0185`). `/Perms` says the metadata is encrypted, as it is, where it said the opposite and readers that check it, pypdf among them, reported a failed verification on every PDF x2t encrypted (`0186`). The old encryption dictionary is no longer copied into the new file, unreferenced, its strings encrypted twice (`0187`).
- *Signatures.* `libera-sign`, a program beside x2t that lists, makes and removes the signatures of an OOXML package, which the host cannot do itself, `ooxmlsignature` having a C++ interface only (`0190`, ours). The signer shown is the certificate's subject, read as UTF-8, where it was the issuer's name, escaped (`0188`), and a certificate's end date has its own day (`0189`).
- *PDF* (`0176` onwards). A form saved as an incremental update leaves its XFA out, so that a reader which shows the XFA, Acrobat, shows the fields as filled rather than the form as it was (`0176`, ours). A saved PDF keeps its Creator, which the writer replaced with the Producer, or with its own name when the Creator was a hex string (`0177`, after ElixirOffice's `0011-pdf-preserve-creator`). A page moved after another keeps the size and rotation it inherits from its own parents, where it took those of the page that had been at its position (`0178`, ElixirOffice's). A value typed into a form field is written on the field, not on the first ancestor that already had one, which every field under it inherits: a LiveCycle form, a French Cerfa for one, keeps an empty value at its root, and one name typed became the value of all its fields (`0179`, ours). An encrypted PDF keeps its file ID at its own length: the key of every encryption but AES-256 is computed over it, and the writer copied 16 bytes of it while counting all of them, so a comment on a PDF pypdf encrypted, with RC4 or AES-128 and a 32-byte ID, was not saved (`0181`, ours). And an incremental update that cannot start writes nothing: the edits after it went into a document never set up, and the save appended an empty update and reported success, where now it copies the original, which the host's check refuses (`0182`, ours).
- *A faster start.* Seven headers defined their constant tables `static`, so every source file including one built its own copy each time x2t started. They are C++17 `inline` variables now, defined once (`0180`, ElixirOffice's `0004-header-statics-inline`): on macOS the converter's library is 74 MB instead of 88, and a small conversion takes 43 ms instead of 60.

**`web-apps`: 11 patches, and `sdkjs`: 30.** Four of web-apps' are build fixes. Theme tokens were not substituted when deploying HTML. Two cap how many tasks a build phase runs at once. The fourth runs `npm` and webpack through `node`, since on Windows both exist only as `.cmd` files that Node will not spawn without a shell. A fifth, making the SVG sprites before the tasks that read them, is upstream's since 2026-11-02. One is a rendering fix, for unsized SVG icons in the language picker rendering at 300×150, the CSS default for a replaced element with no intrinsic size. Three are configuration changes that are ours alone. Two are branding. One drops upstream's favicon. The other keeps *About* reachable in the desktop build, where upstream hides it: that dialog shows the licence and the attribution.

Taking upstream's *Go back* button off the desktop page once took away what the password dialog's *Close file* reads to close the window: the button threw, the error became "An error has occurred while opening the file", and that message's OK threw again. Since v9.3.8 upstream's page names an empty *Go back* itself, which shows no button, and the patch that did so here (`web-apps` `0013`) is gone.

Two are security fixes, from ElixirOffice's fork of `web-apps`, for places where the editor wrote a document's own text into its page as HTML. A document can carry markup there, and the page holds the bridge, so the markup ran beside it. The popup that describes a tracked change inserted the font of a formatting change and a paragraph's new style as the document names them; it ran as soon as the cursor entered the change. The Formula Wizard wrote each argument's value and the results the same way, so a cell holding markup ran it when the wizard was opened on a formula reading that cell. Both now escape what they show. `tests/c_e2e/host/test_hostile_document.py` holds them, beside the places that already showed such text as text: a change's author, a comment, a link's tooltip, a sheet's name. Neither fix is upstream yet.

The two other `sdkjs` patches choose fonts, and come from ElixirOffice's fork of `sdkjs` (AGPL, like the components), each naming the commit it was taken from. `0002` substitutes a missing font the way Word does: a metric-compatible font first (Carlito for Calibri, Caladea for Cambria, Liberation for Arial, Times New Roman and Courier New), and Calibri, hence Carlito, for a font Word would not know either. `0003` draws the characters of a missing Symbol, Wingdings or Webdings as the Unicode symbols they stand for, where they came out as letters. `0006`, ours, finds a font whatever the case of its name, as Word does: a document set in "Open Sans SemiBold" was drawn in a substitute where the font installed is "Open Sans Semibold". `0007`, ElixirOffice's (their commit `3d55711`), sizes an autofit table's columns so that a word fits beside the first-line indent in every compatibility mode, as Word does, where a Word 2007 calendar had "Su" over "n". `0008`, theirs too (the same commit), keeps a run's border in the text properties and the change log and draws it, one box around adjacent runs with equal borders; the change log's text properties had no flag bit left, so the border follows the ligatures byte, marked in two bits older data never sets. `0009`, theirs (commit `de6ba67`), lays out a font size below half a point as half a point, as Word does, so an empty paragraph whose mark has `w:sz="0"` keeps a height; the stored size is left alone. `0010`, theirs (commit `3d55711`), draws a superscript's underline under the raised text, where it was left on the line's baseline. `0011`, theirs (commit `de6ba67`) with two changes of ours, reads, draws and writes back picture bullets: a level's bullet id goes in the change log after `IsLgl`, whose byte's bit 1 says it is there, so that a change log written before still reads, and x2t's renderer, which has no image loader, draws the picture from its address. `0012`, theirs (commit `340aed1dc`), reads the font table core `0204` writes and draws a missing font in its alternate name when that one, or its clone, is installed; merged with `0006`, so an alternate name is found in any case too.

Two more fix Office 2016's extended charts (sunburst, treemap, waterfall, funnel), both ours, after changes ElixirOffice made in 0.9.0 and 0.9.1. `0013` draws an extended chart's title in its chart style's regular face, as Word does, where every chart title was bold. `0014` reads every sheet of a workbook that holds one: x2t writes a drawing as one record, the chart and then the fallback Excel keeps for it, and the reader left the fallback unread when it could draw the chart, so every record after it was misread and a workbook whose sunburst reads another sheet opened with its first sheet alone.

`0015`, ours, after ElixirOffice 0.9.0, saves a Slides table edge the table panel set to "no border" as no line. The panel sets border type nil, and the writer took only none for no border, so it wrote a black line half a point wide and the table came back ruled.

`0016`, after ElixirOffice 0.7.3 (their commit `8f74f43`), keeps a document's compatibility switches (`w:compat`) through a save. x2t hands them to the editor as three words of bits; the editor read the five it lays out by and wrote every other bit as off, and the third word not at all, so a document edited here lost switches such as `noLeading` or `growAutofit` and Word laid it out differently. It now keeps the words as read and writes back the bits it does not model.

`0017`, theirs (the same commit), with core `0207`, reads, lays out and writes back a positional tab: a tab to the left edge, the centre or the right edge of the area between the margins or the indents, whatever the tab stops, as Word lays out a header's centred title and right-aligned page number. It has a change log id of its own, `0x004f`, after the last one at our pin.

`0018`, theirs (the same commit), knows the SET field, which defines a bookmark and of which Word shows nothing. The instruction parser did not know it: a complex SET showed its cached result, and a simple one (`w:fldSimple`) was read as that text alone, so a save lost the field. SET is now field type `0x0017` (theirs is `0x0018`, after an XE type we do not have), and a complex SET hides its result as ASK does. A simple SET is now kept, but still shows its result: their hiding of it, three drawing overrides on `ParaField`, did not hide it, measured, and is left out.

`0019`, theirs (commit `c7eac93`, their 0.9.1), drops a spelling answer the paragraph no longer waits for. A change of the document language checks every paragraph again, but the answer to the request already sent still came back, with the same recalculation id, and was applied to the words of the new language: French text set to French as it opened stayed underlined as English. An answer now counts only if the paragraph still waits for those words in those languages, which the answer carries back.

`0020`, theirs (commit `6f67073`, their 0.9.0, for their #57), places a picture anchored to a paragraph against the column the paragraph's text is in. A paragraph that a picture filling a column pushes whole into the next one leaves an empty piece in the first, and a picture placed against its column was placed against that piece: at the foot of the first column, under the picture that fills it.

`0021`, theirs (commit `8f3b4c4`, their 0.8.0, for their #61), draws a stroke thinner than a pixel in an SVG picture of the document one pixel wide, as core `0200` does for the SVGs x2t makes of WMF and EMF: the loader reads the SVG's text and marks such a stroke `vector-effect="non-scaling-stroke"`, one pixel. It reads the text with an XMLHttpRequest to the picture's `file:///doc/media/` address, which the bridge (`bridge-page.js`) redirects to the host as it does the picture's `src`; without that the request failed and the picture was drawn unchanged.

`0022`, theirs (the same commit), writes a document's style ids back on save. The editor keys its styles by ids it makes up, and a save wrote those, "670" for "Heading1", with every reference renamed. A style read from a file now keeps the file's id, and any other gets one made of its name, as Word makes them, unique against the rest; the ids are mapped wherever one is written (the style itself, based on, next, link, paragraph, character and table styles, and the numbering's links), but not on the clipboard. Their filter that leaves unused built-in styles out of `styles.xml` is not taken: it is a separate change, and a save here writes 66 styles for a document of five, not the 1,850 theirs did.

`0023`, ours, saves an Office 2016 chart whose data holds its values alone, with no formula naming the cells they came from. A save builds each chart's workbook from those values, and read every formula as a string: one with none crashed the writer, and x2t refused to save the document. Such data now fills no cells, and a chart none of whose data names a cell is written with no workbook, where an empty one would have been; it keeps its values in its own part.

`0024`, theirs (commits `8f3b4c4`, their 0.8.0, for their #78 and #79, and `6f67073`, their 0.9.0), draws the extended charts as Office does. A file stores a sunburst's levels deepest first, and the editor built its tree from the leaves out; it now reads them root first, gives each top-level branch the next accent of the theme, where every segment had the first, and names each segment along the radius, the name shrunk, wrapped at spaces or hidden to fit. A treemap is laid out squarified, a colour and a header per branch; a waterfall takes accents for increase, decrease and total, with that legend; a funnel's labels are white; and dragging an extended chart's data label, which stopped the editor, is ignored. Their node tests come with it (`tests/word/sunburst.test.cjs`, `treemap.test.cjs`, `chartex-style.test.cjs`, run with `node --test`), less two: one checks their wording of `0013`'s regular title, and one their *Change Colors* ribbon, which is not taken.

`0025`, ours, guards the desktop layer, so that one build of the editors serves the desktop and a browser. With `SDK_PLATFORM=desktop`, the build adds six files (`common/Local/common.js`, `common/Local/license.js` and each editor's `Local/api.js`) that replace the editors' methods as they load and call what only the desktop host provides, so a desktop build can't edit in a browser. The loader that joins each bundle now wraps them in one block that runs only if `window.AscDesktopEditor` exists. The host defines it before any script runs, and a browser never does. The block holds the files' shared names in one scope, and opens on the line of the separator before them, so the source maps stay exact. Its tests load a desktop build's bundles with and without the host's object (`build/test/sdk-concat.test.cjs`).

`0026` to `0030`, ours, fix what reading a name that nothing defines did, found by `tests/engine/names.mjs`, which lists the namespace members the engine reads and no file defines. Convert Text to Table checked its lock against `changestype_Document_Contentt`, a typo (`0026`). The PDF builder API's field actions read `AscPDF.FORMS_TRIGGERS_TYPES` where the table is `PDF_TRIGGERS_TYPES`, and threw (`0027`). A sheet protection's algorithm went to and from JSON through `AscCommon.CryptoAlgorithmName`, which does not exist, and threw (`0028`), and the XML reader and writer named `SHA1` where the key is `SHA_1`, so SHA-1 was lost (`0029`). A 3D shape's contour and extrusion colours were read from JSON as `ContourClr` and `ExtrusionClr`, classes that do not exist, where the shape holds `CUniColor`s, and the writer lost their type (`0030`). All five are offered to Euro-Office; `tests/engine/patches.test.mjs` holds them.

`0004` is ours: Markdown keeps its headings through a save. Markdown read into a document gives each heading a style derived from a heading style, which the HTML writer, on the way back to Markdown, did not recognise, so `# Title` came back as `**Title**`. It now writes a heading by its outline level, and leaves out a bold that covers the whole heading.

`0005` is ours too, and lets the PDF editor open a PDF at all. `CPDFDoc`'s constructor assigned `widgets`, `annots` and `drawings`, which its prototype defines as getters with no setters, and the bundle's strict mode refuses that: "Cannot set property widgets of #<CPDFDoc> which has only a getter". The patch drops the three assignments.

## One idea per patch

Each patch does one thing and says why. When a patch needs to change, the queue is regenerated from the build tree with `git format-patch`, and is never edited by hand.

Two traps have each cost real time:

**`git am` strips carriage returns.** It parses a patch as mail, so `mailinfo` removes the trailing CR from every line. Any patch touching upstream's CRLF files is then rejected, with nothing to suggest that line endings were the cause. The queue is applied with `--keep-cr`.

**Do not `git add -A` in the build tree.** The payload build stages generated assets into it, so a blanket add sweeps them into your patch.

## Upstreaming

Most of these are upstream's own bugs and should go back.

The `web-apps` fixes are small and self-contained, so they can go as soon as the mirrors exist. The `core` patches are the valuable contribution and have to wait: two of them change platform defines globally, so the Linux build has to confirm they are inert there before we offer a series that could break somebody else's build.

Three patches never leave our tree. `0002` turns off upstream's feature tips and removes their helpdesk links; `0004` retitles the wrapper page; `0008` turns macros off, until there is a macro language worth offering (see [the roadmap](roadmap.md)). They are configuration for a different product.
